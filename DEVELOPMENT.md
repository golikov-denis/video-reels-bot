# Разработка и эксплуатация

## 1. Архитектура

### Управляющая часть — Vercel

Next.js, TypeScript и App Router. Здесь размещаются Telegram webhook, health-check и будущие API задач, Mini App, подписка и диагностика.

### Обработчик видео — следующий отдельный этап

Docker-контейнер на управляемой платформе, FFmpeg, PostgreSQL-очередь с lease/heartbeat, интерфейсы провайдеров распознавания, перевода и анализа, S3-совместимое хранилище и подписанные callback-запросы. Обработчик ещё не создан.

### Данные — следующие этапы

Neon PostgreSQL для пользователей, задач, подписок и идемпотентности. S3-совместимое хранилище для исходников и результатов с TTL. Production и Preview должны использовать разные базы, хранилища и Telegram-ботов. Redis в MVP не добавляется без доказанной необходимости.

## 2. Правила процесса

Обычное изменение:

```text
изменение → npm run check → git status → проверка секретов → commit → push → Vercel READY → health-check
```

Рискованное изменение: отдельная ветка, Vercel Preview, тестовый бот, тестовая БД и хранилище, проверка, затем merge в `main`.

Не использовать localhost.run, Cloudflare Tunnel, VPN-туннели или локальный polling-бот. Полный пользовательский сценарий проверяется только после публичного deployment.

Перед коммитом:

1. Выполнить `npm run check`.
2. Проверить `git status` и `git diff --check`.
3. Убедиться, что `.env`, реальные ключи, видео, архивы и временные снимки не попали в индекс.
4. Не сообщать об успешном deployment до фактического статуса READY.

## 3. Официальные источники

- Next.js installation: https://nextjs.org/docs/app/getting-started/installation
- Next.js Route Handlers: https://nextjs.org/docs/app/getting-started/route-handlers
- Vercel Git deployments: https://vercel.com/docs/git
- Vercel CLI: https://vercel.com/docs/cli
- Telegram Bot API: https://core.telegram.org/bots/api
- Telegram Stars: https://core.telegram.org/bots/payments-stars

На первом этапе webhook использует `secret_token` и проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`. Официальный сайт Telegram был недоступен из среды разработки при первоначальной проверке. Перед этапом подписки необходимо повторно открыть официальную документацию и подтвердить актуальные поля периодических Stars-платежей; платёжный код сейчас отсутствует.

## 4. Безопасность первого этапа

- Секрет webhook сравнивается на сервере с защитой от сравнения по времени.
- Токен Telegram используется только в server Route Handler и скрипте настройки.
- JSON ограничен по размеру; повреждённые и неподдерживаемые запросы отклоняются.
- Ошибки Telegram не возвращают stack trace или внутренние детали.
- Health-check сообщает только факт наличия конфигурации, не её значения.

Идемпотентность Telegram updates, rate limiting и авторизация пользовательских ресурсов будут добавлены вместе с PostgreSQL на этапе задач. До этого webhook не создаёт платных задач и не изменяет пользовательские данные.

## 5. Deployment и откат

1. Создать приватный GitHub-репозиторий и отправить ветку `main`.
2. В Vercel выбрать Add New → Project → Import Git Repository.
3. Framework Preset: Next.js; корень репозитория; команда сборки по умолчанию.
4. Добавить Production environment variables и запустить deployment.
5. Дождаться READY и проверить `/api/health`.
6. Только затем выполнить `npm run webhook:setup` локально с production настройками.

Откат приложения: в Vercel выбрать предыдущий READY deployment и использовать Rollback, либо создать проверенный `git revert` и отправить его в `main`. После отката повторить health-check. Откат базы данных и миграций описывается отдельно до появления первой миграции.

## 6. Мониторинг

- Внешняя проверка: `GET /api/health`, ожидается HTTP 200 и `status: "ok"`.
- Vercel: статус deployment, Function Logs и ошибки Runtime.
- Telegram: `getWebhookInfo`, включая `pending_update_count` и сведения о последней ошибке; токен в вывод не помещать.
- После появления очереди: возраст задачи, lease/heartbeat, повторы, сбои callback и удаление файлов по TTL.

## 7. Известные ограничения

- `/start` сообщает о запуске сервиса, но загрузка видео ещё недоступна.
- Повторные Telegram updates пока не сохраняются в БД; обработчик `/start` не создаёт заказов и списаний.
- Нет Mini App, FFmpeg, очереди, распознавания речи, перевода, субтитров, баннеров, истории, подписки и административной диагностики.
- Нет production URL до первого авторизованного deployment.
- Реальные платные smoke-тесты запрещены без отдельного явного разрешения владельца.

## 8. Стоимость

GitHub и Vercel для каркаса предполагается использовать на существующем бесплатном тарифе владельца; фактические лимиты аккаунта проверяются при входе. Neon, S3, видеообработчик и платные AI API ещё не подключены. Перед их созданием нужно зафиксировать тарифы, лимиты бесплатного использования и ожидаемую стоимость обработки одного видео. Платные ресурсы и API не активируются без подтверждения владельца.

## 9. Следующий проверяемый этап

После подтверждённого первого deployment: схема пользователя и задачи в Neon, безопасная загрузка видеофайла через подписанный URL, проверка MIME/размера/длительности и создание бесплатной задачи. До завершения первого этапа эти функции не начинаются.
